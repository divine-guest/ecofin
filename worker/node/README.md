# Переезд на свой сервер в Yandex Cloud

Здесь лежит всё, что нужно, чтобы сервер ПравоФина работал на обычной
машине в России вместо Cloudflare. Код сервера при этом **не переписан**:
те же 19 файлов из `worker/src` запускаются и там, и там.

## Почему вообще переезжаем

1. **Cloudflare не открывается из России.** Адреса `.workers.dev` попали
   в реестр РКН. Для части посетителей это выглядит не как «сайт
   заблокирован», а как «сайт сломан»: калькуляторы считают (они целиком
   в браузере), а войти и спросить консультанта нельзя.
2. **152-ФЗ, ч. 5 ст. 18.** База с персональными данными россиян должна
   физически находиться в России. Cloudflare D1 — не в России.

## Что здесь есть

| Файл | Зачем |
|---|---|
| `db.mjs` | Прослойка: повторяет четыре метода Cloudflare D1 поверх обычного SQLite. Из-за неё 250 с лишним запросов в коде остались нетронутыми |
| `polyfill.mjs` | Подставляет то, чего в Node нет, а в Workers есть. Главное — `crypto`: на нём держатся пароли и токены |
| `server.mjs` | Точка входа: обычный HTTP вместо `fetch()`, крон вместо триггеров, аккуратное завершение вместо обрыва фоновых задач |
| `cloud-init.yaml` | Инструкция для новой машины: сама ставит всё нужное при первом включении |
| `make-cloud-init.mjs` | Подставляет в неё ключи из `worker/.env` |
| `domain.txt` | Домен сайта. Впишете — сервер сам включит HTTPS |
| `test-db.mjs` | 39 проверок прослойки, офлайн |
| `test-server.mjs` | 34 проверки сервера по HTTP |

## Как запустить у себя на машине

```bash
cd pravofin/worker
npm install
node node/server.mjs
```

Переменные берутся из `worker/.env`, порт — из `PORT` (по умолчанию 8080),
файл базы — из `DB_FILE`.

Проверить:

```bash
API_URL=http://127.0.0.1:8080 node node/test-server.mjs
```

Погонять настоящие сюиты против него:

```bash
API_URL=http://127.0.0.1:8080 DB_FILE=./data/pravofin.db node ../tests/e2e.mjs
```

## Как поднять машину в Yandex Cloud

### Что делаете вы (примерно 15 минут)

Это те шаги, которые нельзя сделать за вас: аккаунт и договор
оформляются на ваше имя, а оплата — с вашей карты.

1. **Регистрация.** `console.yandex.cloud`, вход по Яндекс ID.
2. **Платёжный аккаунт.** Для ИП удобнее по безналичному расчёту:
   тогда расходы идут документами, а не с личной карты.
3. **Подготовьте файл настройки** — на своей машине:
   ```bash
   node worker/node/make-cloud-init.mjs
   ```
   Появится `worker/node/cloud-init.ready.yaml`. В нём уже вписаны все
   ключи из вашего `.env`. **В репозиторий он не попадает** — закрыт
   в `.gitignore`. Никому его не пересылайте.
4. **Создайте виртуальную машину.** Compute Cloud → Создать ВМ:
   - образ: **Ubuntu 24.04 LTS**
   - диск: **SSD, 40 ГБ**
   - вычисления: **4 vCPU, 8 ГБ, доля 100%**
   - публичный адрес: **статический** (чтобы не менялся при перезапуске)
   - раздел **«Метаданные»** → поле `user-data` → вставьте туда
     содержимое `cloud-init.ready.yaml` целиком
   - логин и SSH-ключ можно не задавать: заходить руками не понадобится
5. **Подождите 5–7 минут** и откройте в браузере:
   `http://ПУБЛИЧНЫЙ_АДРЕС/api/health`

   Должно ответить `{"ok":true,...,"db":true}`.

### Что машина сделает сама

- поставит Node 22, nginx, средства сборки, firewall;
- заберёт код из репозитория и положит ключи в `.env`;
- развернёт схему базы со всеми миграциями;
- запустит службу и включит автозапуск;
- каждый час будет делать копию базы (`VACUUM INTO` — целостная копия
  на работающей базе), хранить двое суток;
- каждые пять минут проверять репозиторий: появился новый код — обновится
  сама, но только если он разбирается. Выкатка = обычный `git push`;
- как только в `domain.txt` появится домен и он начнёт показывать на этот
  адрес — выпустит сертификат и включит HTTPS.

### Когда появится домен

1. Купите `.ru` у российского регистратора, на ИП.
2. В DNS сделайте запись `A` на публичный адрес машины.
3. Впишите домен в `worker/node/domain.txt`, закоммитьте, отправьте.

Через пять минут сайт откроется по `https://`. Заходить на сервер не нужно.

## Порядок переключения (чтобы ничего не упало)

1. Машина поднята, `/api/health` отвечает.
2. Перенести базу с Cloudflare: выгрузить D1 в SQL, залить в файл.
3. Прогнать все сюиты против нового адреса — **до** переключения.
4. Поменять адрес API во фронтенде и выложить.
5. Переставить вебхук Telegram на новый домен.
6. Понаблюдать сутки.
7. Выключить воркер на Cloudflare.

До шага 7 старый сервер продолжает работать: если что-то пойдёт не так,
откат — это одна строка во фронтенде.

## Что важно не сломать

**`DB_DRIVER=native` в службе — обязателен.** Запасной драйвер
(`node-sqlite3-wasm`) держит файл базы монопольно: второй процесс не может
даже прочитать её. С ним молча перестанет работать почасовой бэкап,
и узнаете вы об этом в тот день, когда бэкап понадобится. При таком
значении сервер лучше не запустится с понятной причиной, чем будет
работать в режиме, про который никто не знает.

**nginx обязан перезаписывать `X-Real-IP`.** Из этого заголовка сервер
берёт адрес посетителя для ограничения частоты запросов. Если оставить
то, что прислал браузер, ограничение обходится подделкой заголовка.
В конфигурации это уже сделано — не убирайте.
