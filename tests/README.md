# Проверки ПравоФина

318 проверок в 16 сюитах. Бьют по **боевому** серверу — отдельного стенда нет.

## Запуск

```bash
D1_API_TOKEN=<токен> node tests/run-all.mjs
```

Одна сюита отдельно:

```bash
D1_API_TOKEN=<токен> node tests/e2e.mjs
```

Сюите `bot` нужен ещё `TELEGRAM_WEBHOOK_SECRET` из `worker/.env` — без него она пропускает команды.

`D1_API_TOKEN` — токен Cloudflare с правом писать в базу D1. Нужен для двух
вещей: завести временного админа и очистить счётчик попыток между сюитами.

## Правила, без которых прогон врёт

**Не трогать настоящие аккаунты.** Сюиты работают только с адресами на
`@test.ru` и удаляют их за собой. Никогда не выполнять `DELETE FROM users`
целиком: в базе есть живые пользователи.

**Чистить `ratelimit` между сюитами.** Лимит регистраций — 8 в час на адрес.
Он выбирается за пару прогонов, после чего все следующие сюиты падают на
регистрации, хотя сайт исправен. `run-all.mjs` чистит счётчик сам.

**Никаких паролей владельца в тестах.** Раньше сюиты входили под настоящей
почтой владельца с паролем прямо в тексте теста. При пустой базе это создало
бы рабочий аккаунт владельца с общеизвестным паролем, а после смены пароля
половина тестов «падала» на исправном сайте. Теперь `_admin.mjs` заводит
одноразовый аккаунт, повышает его до админа и удаляет за собой.

## Про роль владельца

Получить права владельца в тесте нельзя — и так и задумано: `roleFor()`
выдаёт роль `owner` только по переменной окружения `OWNER_EMAILS`, а запись
`owner` прямо в базу понижается до `admin`. Поэтому владелец проверяется
со стороны админа: что ему отказано там, где должно быть отказано.

## Статическая проверка

Отдельно от сюит есть `check.py` в корне — он не ходит в сеть и ловит
незакрытые теги, ссылки в никуда, кнопки без обработчика и ключи, случайно
попавшие в файлы для браузера. Запускается на каждую отправку кода:

```bash
python check.py
```
