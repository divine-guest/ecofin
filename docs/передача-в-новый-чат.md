## Самое срочное: сайт не работает

`ecofin26.ru` не открывается. Причины известны, обе простые.

**1. Домен смотрит не туда.** A-запись в reg.ru указывает на
`84.201.164.112`. Этот адрес машине больше не принадлежит: владелец
перебирал адреса скриптом `find-good-ip.sh`, и адрес сменился.

**2. У машины, возможно, нет внешнего адреса вовсе.** Выполнялись
команды в Cloud Shell:

- `yc vpc address create --name pravofin-ip ...` — резервирование
  постоянного адреса, результат не подтверждён;
- `yc compute instance remove-one-to-one-nat --name pravofin
  --network-interface-index 0` — отвязка временного адреса, прошла;
- `yc compute instance add-one-to-one-nat ... --public-ip-address ...`
  — **упала**: в этой версии `yc` (1.34) флаг называется `--nat-address`.

То есть адрес отвязан, а новый привязать не успели.

**Что сделать первым делом** (всё в Cloud Shell консоли Yandex Cloud):

```bash
yc vpc address list
yc compute instance add-one-to-one-nat --name pravofin --network-interface-index 0 --nat-address АДРЕС
yc compute instance get --name pravofin --format json | grep -E "status|address"
```

Затем поменять A-запись домена в reg.ru на этот адрес и поставить
TTL 600 (сейчас 21600 — смена расходится шесть часов).

**Что уже проверено и точно работает.** Сервер жив, сайт на нём цел:
запрос с именем домена отвечал `301 Moved Permanently` (наш редирект
на https). По голому адресу отдавался `404` — это нормально, nginx
просто не понимает, какой сайт просят без имени. Чинить сервер не надо,
нужен только адрес и запись в домене.

**Известная ловушка.** `find-good-ip.sh` считает адрес рабочим только
если `/api/health` отвечает кодом 200. Сервер отдаёт 404 на запрос без
имени домена — поэтому скрипт показывает «ноль входов» на любом адресе,
даже на исправном. Его вывод «фильтруется весь диапазон» неверен.

## Доступность из-за рубежа и VPN

Замеры с check-host.net по адресу `158.160.30.228` (пока он был у
машины): порт 443 — ответили Россия и США, остальные точки таймаут;
порт 80 — ответили Польша, США, Кипр, Россия. То есть режется часть
маршрутов, не всё подряд. Для человека с включённым VPN это лотерея.

Решение, если после починки замеры останутся плохими: российский CDN
перед сайтом (принимает запросы на своих адресах, до машины ходит
изнутри страны). Cloudflare не годится — в России работает через раз.

## ЮKassa

Магазин одобрен, ShopID **1462757**. Владелец вставил `YOOKASSA_SHOP_ID`
и `YOOKASSA_SECRET_KEY` в метаданные машины (ключ `extra-env`) — сервер
читает их при запуске и раз в пять минут. Проверить, увидел ли:

```
https://ecofin26.ru/api/billing/plans → "enabled": true
```

Снаружи проверять через `r.jina.ai/https://ecofin26.ru/api/billing/plans`:
curl к своему домену с машины владельца не проходит, allorigins отвечает
522.

Осталось по ЮKassa:

- включить HTTP-уведомления на `https://ecofin26.ru/api/billing/webhook`,
  события `payment.succeeded` и `payment.canceled`;
- попросить у менеджера автоплатежи (сохранение способа оплаты). Без них
  подписка не продлевается сама; оплата при этом работает — код умеет
  повторить платёж без сохранения карты;
- чеки выбраны «от ЮKassa» (2,8% + 1% за чек), категория деятельности —
  «Услуги в сфере информационных технологий».
